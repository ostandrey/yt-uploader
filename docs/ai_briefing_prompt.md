ЩО ЦЕ ЗА ПРОЄКТ
============================================================

Coin Wire — автоматичний крипто-ньюс-канал. Не студія, не людина в кадрі. Воркер (Railway, Python) кілька разів на день: бере свіжу новину з RSS, пише короткий англомовний скрипт, озвучує TTS, збирає вертикальне відео 9:16 (Short/Reel/TikTok-формат) через ffmpeg, заливає на YouTube як Short, шле в Telegram.

Північна зірка продукту: люди ДОДИВЛЮЮТЬСЯ ролик, лайкають і шерять. Платформи — підсилювачі, не мета самі по собі. Зараз канал крихітний; якість ролика важлива, але без дистрибуції ролик помирає в Studio.

Контент: криптоновини (BTC, ETF, Fed, SEC, біржі). Це критично: TikTok for Developers прямо відхилив нашу апку як «Virtual currency / Cryptocurrency related». Будь-яке рішення має переживати crypto-policy, не прикидатися lifestyle-блогером.

Обсяг: орієнтовно 2 Shorts на день + кілька текстових новин у Telegram. Не 50 роликів/годину. Стек має лишатися дешевим CPU-воркером, не GPU-фермою.

Репозиторій: yt-uploader, пайплайн run_coin_wire_pipeline.py, воркер coin_wire_worker.py, конфіг config/coin_wire.yaml.

ЛОГІКА ПАЙПЛАЙНА (ЯК ВОНО ЇДЕ)
============================================================

1) News. RSS: CoinDesk, Cointelegraph, The Block, Decrypt. Фільтр news_filter ставить бал (свіжість, тикер, сила новини). Слабкі «analysis eyes / markets watching» інколи пролазять — це борг якості, не дистрибуції.

2) Dedup. Хеші вже використаних статей у JSON, щоб не знімати одне й те саме.

3) Copy. short_script_generator + copy_writer. Короткий spoken script (~18–28 секунд), хук зі стату в перші ~2с, короткий CTA, бренд outro. Опційно COPY_LLM_* (OpenAI-сумісний JSON) для гострішого тексту. Sprint 2A: обрізка visячих речень («inflows to.»).

4) Voice. Зараз Microsoft Edge TTS, голос en-US-ChristopherNeural, rate +15%. Безкоштовно, часто плоско. Пауза між реченнями зменшена до 0.15с.

5) B-roll. На рендері тягнемо сток з Pexels/Pixabay під тему. Є опційна локальна бібліотека + синк у Cloudflare R2, YOLO/CLIP для індексу «поганий кліп». Живий AI-підбір кліпу під КОЖНУ фразу на момент рендеру — ЗАПАРКОВАНО на 1–2 тижні. Не пропонуй переписувати B-roll зараз, якщо питання про постинг.

6) Render. ffmpeg_short_renderer: 1080x1920, хук-картка, karaoke-субтитри ASS, тікер, xfade, SFX, outro ~1.2с. Це наш «монтажний стіл». Не пропонуй переїзд на Remotion / Shotcut / fal.ai як умову дистрибуції.

7) QA. shorts_qa.py + scripts/review_short.py: правила (довжина, хук, outro, visячі речення) + опційно vision LLM по 4 кадрах, якщо є COPY_LLM_API_KEY. Це фідбек, не автоперезбірка MP4.

8) YouTube. Офіційний Data API v3 + OAuth. Залив unlisted, через ~30 хв воркер робить PUBLIC (kill switch у конфігу). Ламається, якщо на Railway немає volume /app/tokens і валідного YOUTUBE_CRYPTO_TOKEN_JSON, або /app/data не змонтований (рендери зникають після redeploy).

9) Telegram. Офіційний Bot API. Пост у канал (новина) + особисте повідомлення власнику: прев’ю, кнопки publish/hold, тепер ще й сам MP4 + підписи для репосту з телефону. Ліміт бота ~50 МБ на відео.

10) Crosspost. Після рендеру викликається run_crosspost: незалежно TikTok, Instagram, Threads. У yaml усі три enabled: true, але в проді це НЕ працює (див. проблеми нижче). Помилка однієї платформи не повинна валити YouTube.

11) Showrunner/BMAD. Внутрішні ролі (аналітик, архітектор, сторітеллер, відеоредактор) для плану якості. Не плутати з публікацією.

ТЕХНОЛОГІЇ ЗАРАЗ І АЛЬТЕРНАТИВИ (НЕ МІНЯТИ РАДИ МІНИ)
============================================================

Хостинг воркера: Railway. Альтернативи Fly.io, Render, VPS. Важливо не платформа, а persistent volumes для /app/data і /app/tokens. Overlay-диск стирає відео і OAuth на redeploy — це вже кусало.

Новини: RSS + скоринг. Альтернативи: CryptoPanic API, GDELT, платні термінали, worldmonitor-стиль макро. Не треба новий фетчер, щоб почати постити.

Скрипт: шаблони + опційний LLM. Альтернатива: завжди LLM. Дорогої моделі на кожен рядок не треба.

Голос: Edge TTS. Альтернативи в порядку здорового глузду: інший Edge Neural (Guy/Davis) без нових залежностей; платний API ElevenLabs / Cartesia / OpenAI TTS; open TTS на окремій GPU (Kokoro, Chatterbox, IndexTTS) — не всередині цього CPU-воркера. Не клонувати голос і не тягнути RVC.

Монтаж: ffmpeg. Альтернативи Remotion, MoviePy, Shotcut CLI, fal.ai — гірший fit для 25с новин 2×/день. Ідеї таймінгу можна красти, рушій лишати.

Сток: Pexels/Pixabay. Альтернативи Coverr, Storyblocks (платно), генеративне відео (дорого і Off-brand для новин).

Сховище: локальний диск + опційно R2. Для YouTube/TikTok-через-партнера публічний URL часто не потрібен (файл їде з диска або з нашого API). Для класичного Instagram Graph публічний HTTPS обов’язковий — але Graph ми не використовуємо.

YouTube: єдиний «справжній» відео-API, який у нас уже робочий. Це хаб. Альтернативи немає сенсу (PeerTube тощо не дають охоплення).

Telegram: єдиний «справжній» соц-API, який у нас уже робочий. Канал = owned audience. Альтернатива: ще один бот/канал-тізер з лінком на YouTube, коли ролик PUBLIC.

ПРОБЛЕМА TIKTOK (ДЕТАЛЬНО)
============================================================

Офіційний шлях для автоматизації з НАШОГО коду: TikTok Login Kit + Content Posting API. Додаток «Coin Wire Uploader» пройшов підготовку (scopes, sandbox inbox, FILE_UPLOAD чанками, privacy pages) і був відправлений у Production. Рев’юер відхилив категорійно: контент/апка пов’язані з virtual currency / cryptocurrency не апрувляться.

Наслідки, які треба розуміти:
- Повторна подача тієї ж крипто-апки з красивішим текстом не змінить політику.
- Без Production немає video.publish у публічну стрічку від нашого client_key.
- Sandbox і unaudited режим дають чернетки / SELF_ONLY / inbox, не ріст у For You.
- У проді зараз SKIP: немає TIKTOK_ACCESS_TOKEN — і навіть якби був sandbox-токен, публічного автопостингу б не було.
- Неофіційні репо на кшталт TiktokAutoUploader (cookies, web_ms_token) автор сам попереджає: бан акаунта. Це не архітектура.

Обхід, який нас цікавить (легальний): не стати розробником TikTok, а стати КЛІЄНТОМ уже аудованого партнера. Планувальники на кшталт Plann, Buffer, Later, Metricool, Hootsuite, Publer, Postiz, або API-of-APIs на кшталт Ayrshare / Late / Upload-Post: користувач один раз логіниться TikTok у ЇХньому OAuth (їхній app уже Production), далі НАШ воркер шле їм MP4+caption по їхньому REST, вони публікують. Обмеження: партнер може теж різати crypto ads або вимагати Business; органік інколи проходить там, де Login Kit для крипто-апки — ні. Треба перевірити конкретний продукт на crypto + video publish + API (не лише ручний календар у браузері).

Другий обхід: телефон. Бот уже може кинути MP4 і текст у Telegram; людина в додатку TikTok натискає Upload. Це не автоматизація, це міст, поки немає партнера.

Третій «обхід» — чекати зміни політики TikTok. Не план.

============================================================
ПРОБЛЕМА INSTAGRAM (ДЕТАЛЬНО) — GRAPH У НАС НЕМАЄ
============================================================

Єдиний офіційний автопостинг Reels від стороннього сервера — Instagram Graph API (Facebook Login, Business/Creator IG, прив’язка до Facebook Page, scope instagram_content_publish, INSTAGRAM_USER_ID це IG user id не Page id). Graph НЕ приймає файл з диска Railway: Meta сама качає video_url/image_url з публічного HTTPS, тому потрібен світ-читабельний бакет (R2 public dev URL або свій домен). Особистий (non-Business) Instagram цього API не має. Токени гниють (~60 днів long-lived). App Review і Business verification — окремі місяці бюрократії.

Факт оператора: Graph API немає. Не проєктуй «просто ввімкніть META_ACCESS_TOKEN». Код instagram_publisher.py і CROSSPOST_S3_* — заготовка під шлях, який ми свідомо не експлуатуємо.

Що тоді в логах було б, якби код увімкнули як є: SKIP instagram_reel/feed через відсутність публічного media host. Це симптом Graph-шляху, не симптом «Instagram неможливий назавжди».

Обходи без НАШОГО Graph:
- Той самий клас партнерів (Later, Buffer, Metricool, Ayrshare, …): їхній Meta-додаток уже пройшов review; ми OAuth-имось як творець і пушимо Reel через їх API. Це головний кандидат на справжню автоматизацію IG.
- YouTube як джерело + нативні крос-пости Meta, якщо колись з’являться в Creator Studio — зараз на це не розраховувати.
- Телефон: зберегти MP4 з Telegram → Instagram Reels. Fallback.
- Не обхід: scraping instagram.com, private mobile API, cookies. Бан + ToS.

Окремо: навіть у партнера IG часто хоче Business-акаунт. Якщо акаунт особистий — спершу конвертація, інакше жоден легальний API не врятує.

============================================================
ПРОБЛЕМА THREADS (ДЕТАЛЬНО) — GRAPH У НАС НЕМАЄ
============================================================

Офіційний шлях: Threads Graph (graph.threads.net), окремий продукт Meta, окремий токен, не той самий об’єкт що Instagram Page token. У коді є publish_text (ліміт 500 символів) і навіть publish_video (знову ж публічний video_url). Конфіг mode: text. threads_pulse умів би слати додаткові текстові новини.

У тестових прогонах, коли в env ЩОСЬ лежало схоже на токен, API відповідав OAuthException code 190 Failed to decode — тобто токен битий/протух/обрізаний Railway/не той продукт. Це не «полагодь MCP». Будь-який MCP Threads Growth — обгортка того ж Graph.

Факт оператора: Graph немає, токени не підтримуємо, App Review Threads не проходимо. Вважай threads_publisher мертвим, поки хтось явно не вирішить завести Meta Developer з нуля (ми цього не хочемо як передумову).

Обходи без Graph:
- Партнерський API, якщо вміє Threads (багато планувальників Threads додають із запізненням або лише текст). Перевірити support matrix: текст vs відео.
- Постити в Instagram Reel і покладатися на «також у Threads», якщо Meta дає тумблер у нативному додатку — це не серверна автоматизація.
- Текст у Telegram + лінк на YouTube як owned-loop; Threads тоді ручний або через партнера.
- Телефон: вставити готовий caption з Telegram (у нас captions.py вже збирає короткий текст).

Threads без відео все одно корисний як текстовий пульс новини з лінком на Short. Не треба тягнути MP4 у Threads, якщо партнер бере лише TEXT.

X / ІНШІ

Facebook Page — той самий Meta Graph світ; без Graph не плануй окремий Facebook-клієнт у нашому репо.

ТВОЄ ЗАВДАННЯ
============================================================

Спроєктуй, як Coin Wire може АВТОМАТИЧНО (без людини біля екрана) публікувати вже готовий MP4 + caption на TikTok, Instagram Reels і бажано Threads/X, враховуючи:

A) TikTok відхилив НАШ Login Kit через crypto.
B) У нас немає Meta Graph API і ми не хочемо будувати дистрибуцію на «заведи Facebook App Review».
C) YouTube і Telegram офіційно вже вміємо.
D) Воркер Python на Railway, 2 ролики/день, криптоконтент, файл локально після ffmpeg (іноді ще на volume /app/data).
E) Не cookie, не Playwright, не мобільний reverse-engineering.

Відповідь структурою (прозою, можна списки, БЕЗ markdown-таблиць):

1) Коротко підтверди, що зрозумів продукт і обмеження.
2) Карта легальних шляхів автопостингу 2026: партнерські OAuth-apps, API-of-APIs, native official APIs які нам ще доступні. Для кожного: як це стикується з нашим run_crosspost, що з криптою, чи потрібен Business-акаунт, чи потрібен публічний URL файлу, орієнтовна ціна, single-vendor vs кілька.
3) Рекомендована цільова архітектура: один шар «SocialPublisher» у нашому коді, який шле файл на ОДИН провайдер, а провайдер розкидає по мережах. Або поясни, чому краще кілька провайдерів.
4) Конкретні продуктові кандидати (назви) і що перевірити в їх docs за 30 хвилин: TikTok video, IG Reels, Threads, crypto ToS, REST upload з сервера, webhooks статусу, ліміти.
5) Мінімальний план впровадження в цей репо: інтерфейс, env vars, що вимкнути (мертвий Graph/TikTok Login Kit), як не зламати YouTube/Telegram, rollback.
6) Ризики: бан, зміна політики партнера по crypto, прив’язка акаунта, відгук токена, GDPR, що робити якщо партнер теж скаже «no crypto».
7) Що лишити ручним/телефонним, якщо повний автопост на якійсь мережі неможливий.
8) Чого не робити (антипатерни).

Якщо якоїсь деталі API партнера ти не знаєш — так і напиши «перевірити в docs», не вигадуй, що Ayrshare точно пушить crypto TikTok.
